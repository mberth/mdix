## Goal
Make `mdix q` useful for Sprint 1 by emitting a deterministic JSON index of issues so downstream filtering can be done in `jq`.

## Scope (first chunk)
- Command: `mdix q`
- No query language in Sprint 1: no `--where`, no positional expression parsing.
- Deterministic traversal and output ordering.
- Output JSON by default.

## Output requirements
- Output MUST be a JSON list (not wrapped in an object) so consumers can `jq '.[]'` directly.
- Each list item MUST include enough structured metadata to support downstream filtering in `jq` without re-reading files:
  - `path` (relative to root)
  - `frontmatter` (object or null), including `parent`, `status`, `priority`, and `labels` when present

## Acceptance criteria
- From this repo root, `mdix --root plan/issues q` returns valid JSON and deterministic ordering.
- From this repo root, `mdix --root plan/issues q | jq -r '.[] | select(.frontmatter.parent == "mdix-00") | .path'` returns the Sprint 1 child issues.
- From this repo root, `mdix --root plan/issues q | jq -r '.[] | select(.frontmatter.status == "open") | .path'` lists all open issues.
- From this repo root, `mdix --root plan/issues q | jq -r '.[] | select((.frontmatter.labels // []) | index("sprint-1")) | select(.frontmatter.status == "open") | .path'` lists all open Sprint 1 issues.
- From this repo root, `mdix --root plan/issues q | jq '[.[] | select(.frontmatter.status == "open")] | length'` outputs the count of open issues.

## Notes
Full query language (`--where`, expression parsing, etc.) is intentionally deferred to a later issue.
